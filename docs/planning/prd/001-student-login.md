## 1. 목표

공개 회원가입 없이, **이미 명단에 있는 학생만** 학번으로 들어와 비밀번호를 정하고 이후 같은 학번·비밀번호로 로그인한다.

학번: **학년 1자리 + 반 2자리 + 번호 2자리**. 예: `20101` = 2학년 1반 1번. 1·3학년도 `10101`, `30101`. 전교 1~3학년이 쓴다. 18반은 전교 반 수 합계다.

---

## 2. 사용자 시나리오

### US-1: 첫 로그인 (비밀번호 없음)

> 학생으로서, 학번을 넣고 내 이름을 확인한 뒤 비밀번호를 정하고 싶다. 선생님이 넣어 둔 내 계정인지 확인하고 싶어서.

1. `/login`에서 학번 입력 (숫자, 예: `20101`)
2. 명단에 있으면 **이름**을 보여 주고 “본인이 맞나요?” 확인
3. 맞으면 새 비밀번호 + 확인 입력
4. 저장 후 쇼핑몰 홈(`/`)으로 이동

### US-2: 이후 로그인

> 학생으로서, 학번과 비밀번호로 빠르게 다시 들어오고 싶다.

1. 학번 + 비밀번호 입력
2. 맞으면 `/`로 이동
3. 틀리면 “학번 또는 비밀번호가 올바르지 않습니다” (학번 존재 여부는 길게 힌트 주지 않음)

### US-3: 비밀번호 찾기

> 학생으로서, 비밀번호를 잊었을 때 다시 정하고 싶다.

1. `/login/forgot`에서 학번 입력
2. 명단의 **이름**이 보이면 본인 확인
3. 맞으면 새 비밀번호 + 확인 입력 (관리자 초기화 없음)

### US-4: 명단에 없는 학번

> 시스템으로서, 아무나 계정을 만들지 못하게 하고 싶다.

1. 없는 학번이면 가입 폼을 열지 않는다
2. 회원가입 링크·페이지가 없다

---

## 3. 범위

### In Scope

| 기능 | 설명 |
|------|------|
| CSV 명단 | 관리자 학번만 `/admin/students/import`. 컬럼: 학번, 이름, 학년, 반, 번호, role |
| 학번 입력 | 5자리. 힌트 “20101 = 2학년 1반 1번” |
| 이름 확인 | 명단 `name` 표시 후 동의 |
| 비밀번호 설정 | 첫 로그인 또는 찾기 후 |
| 세션 유지 | 브라우저 세션. 로그아웃 |
| 비밀번호 찾기 | 학번 + 이름 확인 후 재설정 |
| 관리자 역할 | 같은 로그인. `role=admin`이면 `/admin` 메뉴 |

### Out of Scope

| 기능 | 사유 |
|------|------|
| 공개 회원가입 | 인터뷰에서 명시적으로 제공 안 함 |
| 소셜 로그인 | 학번 체계와 무관 |
| 이메일·휴대폰 인증 | 가입 정보가 없음 |
| 이메일 관리자 | Q5: 특정 학번이 관리자 |
| 관리자 비밀번호 초기화 | 1차 없음. 학생과 같은 찾기 흐름 |

---

## 4. 화면·URL

| URL | 설명 | 인증 |
|-----|------|------|
| `/login` | 학번(및 비밀번호) 입력 | 비로그인 |
| `/login/setup` | 이름 확인 + 비밀번호 최초 설정 | 학번 확인 직후 임시 상태 |
| `/login/forgot` | 비밀번호 찾기 | 비로그인 |
| `/logout` | 로그아웃 후 `/login` | 로그인 |

로그인한 학생이 `/login`에 오면 `/`로 보낸다.

---

## 5. 완료 기준 (Definition of Done)

- [ ] 명단의 학번만 통과한다
- [ ] 첫 로그인에서 이름이 보이고, 비밀번호를 정한 뒤에만 쇼핑몰에 들어간다
- [ ] 이후에는 학번+비밀번호로 로그인된다
- [ ] 학번+이름 확인으로 비밀번호를 다시 정할 수 있다
- [ ] `role=admin` 학번은 로그인 후 대시보드 메뉴가 보인다
- [ ] `/signup` 같은 공개 가입이 없다
- [ ] 로그아웃이 된다
- [ ] 학번 형식 안내가 화면에 있다
