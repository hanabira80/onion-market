# PRD-002: 쇼핑몰 (목록·상세·찜·포인트 구매)

| 항목 | 내용 |
|------|------|
| Phase | 1 |
| 상태 | 기획 |
| 작성일 | 2026-08-26 |
| 선행 | PRD-001 로그인, PRD-004 상품 데이터 |

---

## 1. 목표

학생이 **일반 쇼핑몰처럼** 굿즈를 둘러보고, 찜하고, **포인트로만** 구매한다. 현금 결제는 Phase 3.

인터뷰에 “상품 목록 페이지”는 따로 적히지 않았지만, 마이페이지의 구매·찜과 “쇼핑몰처럼 정리된 상품”을 위해 Phase 1에 포함한다.

---

## 2. 사용자 시나리오

### US-1: 상품 둘러보기

> 학생으로서, 카테고리별로 정리된 굿즈를 보고 싶다.

1. 로그인 후 `/`에서 판매 중인 상품 카드(사진, 이름, 포인트, 남은 수량)를 본다
2. 카테고리로 걸러 본다
3. 카드 클릭 → `/products/[id]` 상세 (사진, **컨디션**, **판매 상태**, 포인트, 수량, 카테고리)

### US-2: 찜하기

> 학생으로서, 나중에 살지 고민하는 물건을 저장하고 싶다.

1. 목록 또는 상세에서 찜 토글
2. 마이페이지 찜 목록과 동기화 (PRD-003)

### US-3: 포인트로 구매

> 학생으로서, 포인트가 충분하면 그 굿즈를 사고 싶다.

1. 상세에서 “포인트로 구매” (필요 포인트·내 잔액 표시)
2. 잔액 ≥ 가격 이고 수량 > 0 이면 확인 모달
3. 성공: 포인트 차감, 수량 -1, 구매 목록에 추가
4. 실패: 잔액 부족 / 품절. **동시에 두 명이면 먼저 성공한 사람만** 사고 나머지는 품절
5. 주문 상태 `수령 대기`. 실물은 교실 또는 선생님에게 받음

### US-4: 수령 전 취소

> 학생으로서, 아직 물건을 받기 전이면 주문을 취소하고 포인트를 돌려받고 싶다.

1. `/me/orders`에서 `수령 대기` 주문에 “취소”
2. 포인트 환급, 상품 수량 복구, 주문은 `취소`
3. 이미 수령 완료면 취소 버튼 없음

## 3. 범위

### In Scope

| 기능 | 설명 |
|------|------|
| 목록 | 사진, 이름, 필요 포인트, 수량. 품절은 카드에 표시하되 숨기지 않거나 맨 뒤 (구현 시 한 가지로) |
| 카테고리 필터 | 관리자가 넣은 카테고리 |
| 상세 | 사진, 컨디션(상/중/하), 판매 상태(판매중/예약/완료), 포인트, 수량, 카테고리, 찜, 구매 |
| 찜 토글 | 학생당 상품 1회 |
| 포인트 구매 | DB에서 잔액·수량을 한 번에 갱신. 진 사람은 품절 |
| 수령 전 취소 | PRD-003과 공유 |

### Out of Scope

| 기능 | 사유 |
|------|------|
| 검색창 | 1차 미언급. 카테고리로 충분 |
| 장바구니 여러 개 | 굿즈 1점 단위가 자연스러움. 요청 시 추가 |
| 리뷰·댓글 | 미언급 |
| 토스/현금 | Phase 3 |
| 기부 버튼 | Q1: 실물만. 앱 신청 없음 |
| 대기열 | Q10: 선점만 |

## 4. 화면·URL

| URL | 설명 | 인증 |
|-----|------|------|
| `/` | 상품 목록 (홈 = 몰) | 학생 로그인 |
| `/products/[id]` | 상품 상세 | 학생 로그인 |
| `/category/[slug]` | 카테고리 목록 (선택, `/` 쿼리로 대체 가능) | 학생 로그인 |

비로그인 접근 시 `/login`으로.

---

## 5. 완료 기준 (Definition of Done)

- [ ] 로그인 학생만 목록·상세를 본다
- [ ] 카드/상세에 사진, 컨디션, 판매 상태, 포인트, 수량, 카테고리가 있다
- [ ] 카테고리로 걸러진다
- [ ] 찜 추가/해제가 된다
- [ ] 포인트가 충분하고 수량이 있으면 구매된다
- [ ] 구매 후 잔액·수량·구매 목록이 맞다
- [ ] 잔액 부족·품절 시 차감되지 않는다
- [ ] 동시 구매 시 한 명만 성공하고 나머지는 품절이다
