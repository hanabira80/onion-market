# PRD-004: 관리자 대시보드 · 상품 업로드 · 포인트 지급

| 항목 | 내용 |
|------|------|
| Phase | 1 |
| 상태 | 기획 |
| 작성일 | 2026-08-26 |
| 관련 | Q1 실물+수동 지급, Q5 학번 관리자, Q6 이중 상태, Q7 개별+일괄 |

---

## 1. 목표

`role=admin`인 **학번**이 같은 로그인으로 들어와, 기부받은 굿즈를 몰에 올리고, 기부한 학생에게 포인트를 준다. 학생용 기부 신청 화면은 없다.

---

## 2. 사용자 시나리오

### US-1: 상품 등록

> 관리자로서, 받은 굿즈를 몰에 올리고 싶다.

1. `/admin/products/new`에서 사진, 이름, 컨디션, 판매 상태, 구매 포인트, 수량, 카테고리 입력
2. 저장하면 학생 목록(`/`)에 나타난다 (판매중일 때)

### US-2: 상품 수정

> 포인트·수량·판매 상태를 고친다.

1. 목록에서 선택 후 수정
2. 수량 0 또는 판매 상태 `완료`면 학생은 구매할 수 없다
3. `예약`이면 목록에는 보이되 구매 버튼은 비활성 (초안)

### US-3: 개별 포인트 지급

> 물건을 가져온 학생에게 포인트를 더한다.

1. `/admin/points`에서 학번/이름 검색
2. 지급 포인트와 메모 (예: “키링 기부”)
3. 잔액 즉시 증가, 이력 남김

### US-4: 행사 일괄 지급

> 여러 명에게 같은 포인트를 한 번에 준다.

1. CSV의 학번 목록 또는 체크박스로 대상 선택
2. 1인당 포인트 + 메모
3. 각 학생 잔액 증가, 이력 남김

### US-5: 명단 CSV

> 학년 초·중간에 전교 명단을 올린다.

1. `/admin/students/import`에 CSV (학번, 이름, 학년, 반, 번호, role)
2. 기존 학번은 이름·role 갱신, 없는 학번은 추가. 삭제 정책은 1차: 올리지 않은 학번은 비활성만 (데이터 보존)
3. 최초 1회는 시드 관리자 학번이 있어야 이 화면에 들어올 수 있다

### US-6: 수령 완료

> 학생이 교실에서 물건을 가져가면 주문을 닫는다.

1. `/admin/orders`에서 `수령 대기` → `수령 완료`
2. 이후 학생은 취소할 수 없다

## 3. 범위

### In Scope

| 기능 | 설명 |
|------|------|
| `/admin` 가드 | `role=admin` 학번만. 일반 학생은 `/` |
| 상품 CRUD | 사진(1차 대표 1장), 컨디션, 판매 상태, 포인트, 수량, 카테고리 |
| 개별 포인트 | 검색 후 지급 |
| 일괄 포인트 | 다수 학생 + 동일 금액 |
| CSV 명단 | Q3 |
| 수령 처리 | Q9와 맞물림 |

**상품 필드:**

| 필드 | 설명 |
|------|------|
| 사진 | 1차 대표 1장 |
| 컨디션 | 상 / 중 / 하 |
| 판매 상태 | 판매중 / 예약 / 완료 |
| 구매 포인트 | 양수 정수 |
| 수량 | 0 이상 정수 |
| 카테고리 | 초안: 문구, 학용품, 패션, 기타 |

### Out of Scope

| 기능 | 사유 |
|------|------|
| 학생 기부 신청 화면 | Q1 |
| 이메일 관리자 | Q5 |
| 통계 차트 | 1차 최소 |
| 토스 정산 | Phase 3 |
| 멀티 학교 | Phase 4 |

## 5. 완료 기준 (Definition of Done)

- [ ] 관리자 학번만 `/admin`에 들어간다

- [ ] 판매중 + 수량>0 만 학생 구매가 된다
- [ ] 학번 검색 후 포인트를 줄 수 있다

- [ ] CSV로 명단을 올릴 수 있다
- [ ] 수령 완료 처리가 되고, 그 주문은 학생이 취소하지 못한다
