# ADR-002: 학번 로그인 · 회원가입 없음

| 항목 | 내용 |
|------|------|
| 상태 | 확정 |
| 날짜 | 2026-08-26 |
| 관련 PRD | [../planning/prd/001-student-login.md](../planning/prd/001-student-login.md) |

---

## 컨텍스트

학생은 **학번으로만** 들어온다. 공개 회원가입은 없다. 첫 로그인에서 이름을 확인하고 비밀번호를 정한다. 이메일·휴대폰이 기본 식별자가 아니다.

학번 예: `20101` = 2학년 1반 1번. **학년 1 + 반 2 + 번호 2.** 1·2·3학년 모두 (`10101`, `30101`). 18반은 전교 반 수 합계.

관리자도 **학번 로그인**이다. CSV `role=admin`.

---

## 검토한 대안

| 대안 | 장점 | 단점 |
|------|------|------|
| A. 명단을 `students`에 사전 등록. 학번=로그인 ID. Supabase Auth 사용자와 1:1 (email을 `학번@internal` 같은 내부값으로 쓰거나 custom) | 세션·RLS를 Auth에 맡김 | 이메일 없는 Auth는 설정이 까다로움 |
| B. 자체 `students.password_hash` + 쿠키 세션 | 학번 모델과 잘 맞음 | 세션·CSRF를 직접 관리 |
| C. 매직 링크 / 소셜 | 구현 예시 많음 | 이메일 없음, 학번 요구와 불일치 |

---

## 결정

**A를 1순위로 시도한다.** 학생 행을 CSV로 넣고, 첫 비밀번호 설정 때 Auth 사용자를 만든다. 로그인 ID는 학번이다.

여의치 않으면 **B**. 공개 `/signup`은 없다.

관리자는 별도 이메일이 아니라 **`role=admin` 학번**이다. 최초 1명은 시드하거나 첫 CSV에 넣는다.

비밀번호 찾기: 학번 + 이름 확인 후 재설정. 이메일 리셋 없음.

---

## 결과·영향

- CSV 명단이 로그인 전제다. 컬럼: 학번, 이름, 학년, 반, 번호, role
- RLS: 학생은 자기 행·자기 주문만. admin은 상품·포인트·주문 수령
- 비밀번호 찾기는 이메일을 쓰지 않는다
